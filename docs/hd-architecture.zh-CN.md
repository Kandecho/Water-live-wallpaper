**三个核心：app 驱动，world 更新，renderer 绘制。** 风是场景内部的一项运动；高清细节来自预制素材与少量绘制步骤。

本图依据 HD 1.0.0 源码。轻风与强风共存于同一场景，使用一个安装包。

## A 运行时总图

```flow TB
[宿主与输入] -> [app.js 主循环]: 点击、暂停、帧率
app.js 主循环 -> [world.js 场景]: update(dt)
app.js 主循环 -> [renderer.js 绘制]: 到绘制时刻再 draw()
world.js 场景 -> [wind.js 风调度]: 按模拟时间推进
world.js 场景 -> renderer.js 绘制: 叶子状态与水面采样
[shaders.js 着色程序] -> renderer.js 绘制: 三组 GLSL 程序
[assets.js / maps.js 预制贴图] -> renderer.js 绘制: 启动时上传
renderer.js 绘制 -> [WebGL 画面]: 水面、接触、阴影、叶片
```

箭头表示调用或数据流。`settings.js` 是共享参数入口，供场景、风、着色器和应用读取。
`index.html` 只提供画布并按顺序加载脚本。预览控件按需加载，见后面的职责表。

## B 从原版继承什么

| 原版源码中的做法 | HD 的对应做法 | 保持简洁的边界 |
| --- | --- | --- |
| `FallRS.java` 创建网格、程序并加载贴图 | `renderer.create()` 准备 WebGL 资源 | 素材处理留在离线阶段 |
| `fall.rs` 保存 14 片叶子、10 个波源 | `world` 保存 14 片叶子、最多 12 个波源 | 小数组足够，不引入实体框架 |
| 按距离计算水波，用坡度偏移纹理 | 公式计算波高与导数，偏移背景采样 | 保留解析波形，无需流体求解器 |
| `main()` 直接推进并按顺序绘制 | `app → world.update → renderer.draw` | 直接函数调用，无需消息总线 |
| 叶子用图集中的四边形绘制 | 沿用四边形，加光照与贴水细节 | 局部网格弯曲保留在废案中 |

原版根据实际经过时间计算 `dt`，上限为 0.2 秒，并请求 30 毫秒后的下一帧。
HD 也限制单次 `dt`，绘制上限为 60 FPS；模拟随浏览器动画回调推进。

## C 一帧怎样形成

```sequence num
participants: app, world, wind, renderer, WebGL
app -> world: update(dt)
world -> wind: 到边界时推进风调度
world -> world: 更新叶子、波源和贴水状态
app -> renderer: 达到绘制间隔时 draw()
renderer -> world: mesh() 与局部水面采样
renderer -> WebGL: 绘制水面
renderer -> renderer: 每片叶子计算一次姿态
renderer -> WebGL: 接触细纹 → 阴影 → 叶片
```

暂停时不推进场景。预览对照可以只重绘，因此不会改时间、叶子位置或随机风安排。
`world.update()` 在起风和停风时刻拆分时间步，避免帧率改变事件时刻。

接触效果开启时，先在 GPU 上复制一次水面画面。接触细纹使用这份纹理；运行时不回读 CPU。
姿态在接触、阴影和叶片之间共享，树荫贴图只影响叶片主光照。

## D 风只需一个小调度器

```flow LR
[分别随机等待] -> [选择先到期者]: 当前无风且平静间隔已过
选择先到期者 -> [开始一阵风]: 随机方向、固定整阵
开始一阵风 -> [平滑增强再减弱]: 轻风 13 秒 / 强风 10 秒
平滑增强再减弱 -> [结束并安排下一次]: 只重抽刚结束的种类
结束并安排下一次 -> [平静 2–5 秒]: 期间保留另一种到期时间
```

平静间隔结束后，重新选择先到期者；若都未到期，继续等待。
另一种风到点时只保留原到期时间，每种最多等待一次。当前风不会被打断。

| 调度状态 | 保存的内容 |
| --- | --- |
| `next` | 轻风、强风各一个到期时刻 |
| `active` | 最多一阵风的种类、起止时刻与方向 |
| `readyAt` | 最早允许再次起风的时刻 |
| `effect` | 当前或上一阵风的力度，供残余速度衰减 |

轻风结束后随机等待 25–45 秒；强风等待 150–240 秒。启动时也用这两个范围。
碰到另一阵风时会延后，因此它们不是固定的起风周期。

风使用独立随机序列。叶子回收、重绘次数和水面采样都不会重新抽取风向。
预览按钮也走同一套请求规则，不维护另一套手动风模拟。

## E 运行前准备，运行时使用

```flow LR
[AOSP 原始图片] -> [离线高清化]: 保留形状与图集布局
离线高清化 -> [离线贴图构建]: 树荫、接触、阴影
离线贴图构建 -> [assets.js + maps.js]: 嵌入素材
assets.js + maps.js -> [单一 HD 安装包]: 连同脚本与配置文档
```

离线高清化使用 `upscale-background.py`、`upscale-leaves.py`。
`build-hd-maps.py` 读取配置和派生图片，生成嵌入资源；`package-hd.ps1` 复制文件并打包。

运行时只加载已准备好的资源。Node.js、Python、高清化模型和参考素材均不随壁纸启动。
改变风的时长或强度只需修改 `settings.js` 后重载；美术标定变更才需要重建贴图。

## F 模块边界与后续改动位置

| 责任 | 所属文件 | 后续修改放在哪里 |
| --- | --- | --- |
| 启动、输入、暂停、帧率 | `app.js` | 壁纸引擎适配、鼠标行为 |
| 场景时间、叶子、波源、风实例 | `world.js` | 漂移、落水、波面响应 |
| 风的等待与互斥 | `wind.js` | 风类型、排队、随机方向规则 |
| GPU 资源、尺寸、绘制顺序 | `renderer.js` | 纹理上传、绘制步骤 |
| 像素计算与共享投影变换 | `shaders.js` | 水光、树荫、叶缘明暗 |
| 统一参数与离线标定 | `settings.js` | 调整数值，保持配置无副作用 |
| 预览按钮、快捷键、状态 | `preview-controls.js / .css` | 可视对照，调用现有场景接口 |

`world` 与 `wind` 不依赖 DOM 或 WebGL，可以直接用 Node 测试。
预览模块借用场景与选项；普通壁纸不加载它。`renderer` 读取场景，并在尺寸变化时调用 `world.resize()`。

**保留现在的分工即可。** 风已因互斥和随机时序形成独立职责；着色器也适合集中维护。
其它小函数继续留在所属模块，后续只在真实职责出现时再拆分。
